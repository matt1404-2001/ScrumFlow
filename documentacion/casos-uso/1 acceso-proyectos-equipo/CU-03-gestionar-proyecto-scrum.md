| **CU-01** | **Gestionar proyecto Scrum** |
| **Fecha de creación** | 05/10/2026 |
| **Versión** | 1 |
| **Autor** | Equipo |
| **Actores** | **Usuario autenticado:** puede crear, consultar y seleccionar proyectos. **Administrador del proyecto:** puede modificar su información general. **Sistema:** aplicación web, API y base de datos. |
| **Requisitos previos** | 1. El usuario debe haber iniciado sesión. 2. Para consultar o seleccionar un proyecto, el usuario debe ser miembro. 3. Para modificarlo, el usuario debe ser administrador del proyecto. 4. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Permitir que un usuario cree, consulte y seleccione proyectos Scrum. 2. Registrar al creador como miembro y administrador inicial. 3. Mantener actualizada la información general del proyecto. |
| **Descripción** | Este caso de uso permite al usuario crear, consultar, seleccionar y editar proyectos Scrum a los que pertenece. Al crear un proyecto, el sistema incorpora automáticamente al creador como miembro y administrador inicial, sin asignarle una responsabilidad Scrum. Las responsabilidades del equipo, la Definition of Done y los demás acuerdos se gestionan mediante el submódulo correspondiente, mientras que el Product Goal se administra desde el Product Backlog. La eliminación definitiva de proyectos queda fuera del alcance inicial. |
| **Entradas** | **Proporcionadas por el usuario:** acción solicitada, nombre del proyecto y descripción opcional.  **Internas del sistema:** identidad y sesión del usuario, proyectos a los que pertenece, membresías y permisos de administración.  **Disparador:** el caso comienza cuando un usuario autenticado accede al selector de proyectos o selecciona “Crear proyecto”. |
| **Secuencia normal** | 1. El usuario accede al área autenticada y selecciona “Crear proyecto”. 2. El sistema muestra un formulario con nombre y descripción. 3. El usuario completa la información y selecciona “Crear proyecto”. 4. La aplicación elimina los espacios exteriores y valida los datos. 5. El servidor confirma que la sesión sea válida. 6. El sistema crea el proyecto y registra al creador como miembro y administrador inicial, sin asignarle una responsabilidad Scrum. 7. El sistema guarda el proyecto y la membresía como una única operación. 8. La aplicación establece el nuevo proyecto como contexto activo. 9. El sistema muestra su resumen e indica que deben configurarse el equipo, las responsabilidades Scrum y la Definition of Done. 10. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | **A1. Consultar o seleccionar un proyecto:** el sistema muestra únicamente los proyectos del usuario; al seleccionar uno, comprueba la membresía, lo establece como contexto activo y muestra su resumen.  **A2. Editar información general:** un administrador modifica el nombre o la descripción; el sistema valida y guarda los cambios.  **A3. Información inválida:** si el nombre está vacío o contiene solamente espacios, la aplicación señala el campo y no envía la solicitud.  **A4. Acceso no autorizado:** si el usuario intenta consultar un proyecto ajeno o modificar uno sin ser administrador, el servidor rechaza la operación.  **A5. Error de comunicación o almacenamiento:** el sistema no crea ni actualiza parcialmente el proyecto, informa el problema y permite reintentar. |
| **validaciones** | 1. El usuario debe mantener una sesión válida durante la operación. 2. El nombre es obligatorio, debe eliminar espacios exteriores y no puede quedar vacío; la descripción es opcional. 3. El nombre y la descripción deben tratarse como texto sin ejecutar HTML o scripts. 4. El usuario solo puede consultar y seleccionar proyectos en los que sea miembro. 5. Solo un administrador puede modificar la información general. 6. La creación debe registrar conjuntamente el proyecto y al creador como miembro y administrador inicial, sin asignarle responsabilidades Scrum. 7. El proyecto debe conservar al menos un administrador y no puede eliminarse definitivamente desde esta función. |
| **Mensaje de Sistema** | 1. Creación exitosa: “Proyecto creado correctamente”. 2. Actualización exitosa: “Información del proyecto actualizada”. 3. Nombre inválido: “Ingresa un nombre para el proyecto”. 4. Acceso denegado: “No tienes permiso para realizar esta acción”. 5. Proyecto no disponible: “No fue posible encontrar el proyecto solicitado”. 6. Error general: “No fue posible guardar el proyecto. Inténtalo nuevamente”. |
| **Salida de Sistema** | 1. Proyecto creado o información general actualizada. 2. Creador registrado como miembro y administrador inicial, sin responsabilidad Scrum asignada. 3. Proyecto seleccionado como contexto activo cuando corresponda. 4. Resumen del proyecto disponible con sus configuraciones pendientes. |
