| **CU-01** | **Registrar usuario** |
| **Fecha de creación** | 05/10/2026 |
| **Versión** | 1 |
| **Autor** | Equipo |
| **Actores** | **Usuario no registrado:** persona que desea crear una cuenta. **Sistema:** aplicación web, API y base de datos. |
| **Requisitos previos** | 1. El usuario debe tener acceso a la aplicación web. 2. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Permitir que una persona cree una cuenta desde la aplicación. 2. Registrar el nombre y correo electrónico del usuario. 3. Garantizar que el correo no esté asociado con otra cuenta. 4. Proteger la contraseña mediante un mecanismo seguro de hash. 5. Crear una cuenta activa que pueda utilizarse para iniciar sesión. 6. Permitir que el usuario pueda crear proyectos o recibir invitaciones posteriormente. |
| **Descripción** | Este caso de uso permite que una persona cree una cuenta proporcionando su nombre, correo electrónico, contraseña y confirmación de contraseña. El sistema valida los datos, comprueba que el correo sea único y almacena la contraseña mediante un hash seguro de una sola vía. Cuando el registro finaliza correctamente, la cuenta queda activa y la persona es dirigida a la pantalla de inicio de sesión. El registro no inicia sesión automáticamente ni incorpora al usuario a un proyecto Scrum. |
| **Entradas** | **Entradas proporcionadas por el usuario:** - Nombre. - Correo electrónico. - Contraseña. - Confirmación de contraseña. - Selección de la opción “Crear cuenta”.  **Entradas internas del sistema:** - Correos electrónicos registrados. - Reglas de validación de contraseña. - Fecha y hora actual del servidor.  **Disparador:** El caso de uso comienza cuando una persona sin sesión activa selecciona la opción “Crear cuenta” desde la pantalla de inicio de sesión. |
| **Secuencia normal** | 1. La persona accede a la pantalla de inicio de sesión.  2. El sistema muestra la opción “Crear cuenta”.  3. La persona selecciona “Crear cuenta”.  4. El sistema comprueba que no exista una sesión activa.  5. El sistema muestra el formulario de registro.  6. La persona introduce su nombre.  7. La persona introduce su correo electrónico.  8. La persona introduce una contraseña.  9. La persona vuelve a introducir la contraseña en el campo de confirmación.  10. La aplicación elimina los espacios exteriores del nombre y del correo.  11. La aplicación normaliza el correo para su comparación.  12. La aplicación comprueba que todos los campos estén completos.  13. La aplicación comprueba que el nombre y el correo tengan un formato válido.  14. La aplicación comprueba que la contraseña contenga al menos 12 caracteres, un número y un símbolo.  15. La aplicación comprueba que la contraseña y su confirmación coincidan exactamente.  16. La persona selecciona la opción “Crear cuenta”.  17. La aplicación envía los datos al servidor mediante una conexión segura.  18. El servidor vuelve a validar todos los datos recibidos.  19. El servidor comprueba que no exista otra cuenta con el mismo correo normalizado.  20. El servidor genera un hash seguro de la contraseña utilizando una sal única.  21. El servidor crea la cuenta en estado activo.  22. El servidor guarda el nombre, el correo normalizado, el hash de la contraseña y la fecha de creación.  23. El servidor confirma que la cuenta fue creada correctamente.  24. La aplicación informa que el registro fue exitoso.  25. La aplicación dirige al usuario a la pantalla de inicio de sesión.  26. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | A1. El usuario ya tiene una sesión activa  1. En el paso 4, el sistema detecta una sesión válida.  2. El sistema no muestra el formulario de registro.  3. La aplicación dirige al usuario al área autenticada.  A2. Existen campos incompletos  1. En el paso 12, la aplicación detecta uno o más campos vacíos.  2. La aplicación no envía la solicitud al servidor.  3. El sistema señala los campos que deben completarse.  4. La persona permanece en el formulario.  A3. El nombre no es válido  1. En el paso 13, la aplicación detecta que el nombre está vacío después de eliminar sus espacios exteriores.  2. La aplicación no envía la solicitud.  3. El sistema solicita introducir un nombre válido.  A4. El correo no tiene un formato válido  1. En el paso 13, la aplicación detecta que el correo no cumple el formato esperado.  2. La aplicación no envía la solicitud.  3. El sistema solicita introducir un correo válido.  A5. La contraseña no cumple los requisitos  1. En el paso 14, la aplicación detecta que la contraseña no cumple la longitud o composición requerida.  2. La aplicación no envía la solicitud.  3. El sistema informa los requisitos de la contraseña.  A6. Las contraseñas no coinciden  1. En el paso 15, la aplicación detecta que la contraseña y su confirmación son diferentes.  2. La aplicación no envía la solicitud.  3. El sistema solicita revisar la confirmación.  A7. El correo ya está registrado  1. En el paso 19, el servidor encuentra una cuenta con el mismo correo normalizado.  2. El servidor rechaza la solicitud.  3. No se crea una segunda cuenta.  4. El sistema informa que el correo ya está registrado.  5. La persona puede utilizar otro correo o dirigirse al inicio de sesión.  A8. No se puede contactar con el servidor  1. En el paso 17, la aplicación no logra comunicarse con la API.  2. El sistema informa que no fue posible establecer comunicación.  3. La persona permanece en el formulario.  4. La persona puede reintentar la operación.  A9. No se puede guardar la cuenta  1. En los pasos 21 o 22, ocurre un error antes de confirmar el registro.  2. El sistema cancela la operación completa.  3. No debe quedar una cuenta parcialmente registrada.  4. El sistema informa que no fue posible crear la cuenta. |
| **validaciones** | 1. Todos los campos del formulario son obligatorios.  2. Deben eliminarse los espacios exteriores del nombre y del correo; el nombre no puede quedar vacío y debe tratarse como texto sin ejecutar HTML o scripts. 3. El correo debe tener un formato válido, normalizarse para su comparación y ser único sin distinguir mayúsculas y minúsculas. 4. La contraseña debe contener al menos 12 caracteres, un número y un símbolo. 5. La contraseña no debe recortarse ni normalizarse, y su confirmación debe coincidir exactamente. 6. Todas las validaciones deben repetirse en el servidor antes de crear la cuenta. 7. La contraseña debe almacenarse mediante un hash seguro con sal única y nunca conservarse ni registrarse como texto visible. 8. La creación de la cuenta debe completarse totalmente o cancelarse totalmente. 9. La cuenta debe quedar activa, pero el registro no debe iniciar sesión automáticamente. 10. El registro no debe crear proyectos ni membresías; el usuario solo ingresa a un proyecto al crearlo o aceptar una invitación. | |
| **Mensaje de Sistema** | 1. Registro exitoso: “Cuenta creada correctamente. Ya puedes iniciar sesión”.  2. Datos incompletos: “Completa todos los campos obligatorios”.  3. Nombre inválido: “Ingresa un nombre válido”.  4. Correo inválido: “Ingresa un correo electrónico válido”.  5. Contraseña inválida: “La contraseña debe tener al menos 12 caracteres, un número y un símbolo”.  6. Confirmación incorrecta: “Las contraseñas no coinciden”.  7. Correo registrado: “Ya existe una cuenta con ese correo electrónico”.  8. Error de comunicación: “No fue posible comunicarse con el servidor”.  9. Error al guardar: “No fue posible crear la cuenta. Inténtalo nuevamente”. |
| **Salida de Sistema** | 1. Nueva cuenta registrada y activa.  2. Nombre asociado con la cuenta. |
