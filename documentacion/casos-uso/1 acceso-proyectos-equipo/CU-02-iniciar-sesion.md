| **CU-02** | **Iniciar sesión** |
| **Fecha de creación** | 05/10/2026 |
| **Versión** | 1 |
| **Autor** | Equipo |
| **Actores** | **Usuario registrado:** persona que desea acceder a su cuenta. **Sistema:** aplicación web, API y base de datos. |
| **Requisitos previos** | 1. El usuario debe poseer una cuenta registrada y activa. 2. El usuario debe tener acceso a la aplicación web. 3. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Verificar la identidad del usuario y establecer una sesión segura. 2. Permitir el acceso a sus proyectos e invitaciones. 3. Mantener al usuario identificado durante sus operaciones y permitirle cerrar la sesión. |
| **Descripción** | Este caso de uso permite que un usuario registrado acceda al sistema mediante su correo y contraseña. Si las credenciales son correctas, el sistema establece una sesión segura y muestra el área autenticada con sus proyectos e invitaciones. La sesión permanece vigente hasta que expire o el usuario seleccione “Cerrar sesión”. |
| **Entradas** | **Proporcionadas por el usuario:** correo electrónico, contraseña y selección de “Iniciar sesión”.  **Internas del sistema:** cuentas registradas, credenciales protegidas, proyectos, membresías, invitaciones pendientes y fecha actual.  **Disparador:** el caso comienza cuando un usuario sin sesión válida accede a la aplicación. |
| **Secuencia normal** | 1. El usuario accede a la aplicación y el sistema comprueba que no exista una sesión válida. 2. El sistema muestra el formulario de inicio de sesión. 3. El usuario introduce su correo y contraseña. 4. La aplicación normaliza el correo y valida que los datos estén completos y tengan un formato válido. 5. El usuario selecciona “Iniciar sesión”. 6. La aplicación envía las credenciales al servidor mediante una conexión segura. 7. El servidor localiza la cuenta y compara la contraseña con la credencial protegida almacenada. 8. El servidor confirma las credenciales y genera una sesión segura con tiempo de expiración. 9. El servidor devuelve la información básica del usuario, sus proyectos y sus invitaciones pendientes. 10. La aplicación conserva la credencial de sesión de forma segura y muestra un mensaje de confirmación. 11. La aplicación dirige al usuario al área autenticada y el caso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | **A1. Ya existe una sesión válida:** en el paso 1, el sistema omite el formulario y dirige al usuario al área autenticada.  **A2. Los datos están incompletos o el correo es inválido:** en el paso 4, la aplicación señala los campos que deben corregirse y no envía la solicitud.  **A3. Las credenciales son incorrectas:** en el paso 7, el servidor rechaza la solicitud sin indicar cuál dato es incorrecto; el usuario permanece en el formulario y puede intentarlo nuevamente.  **A4. Ocurre un error de comunicación o del servidor:** en los pasos 6 a 9, el sistema no crea la sesión, informa el problema y permite reintentar la operación.  **A5. Cerrar sesión:** después de autenticarse, el usuario selecciona “Cerrar sesión”; el servidor invalida la sesión, la aplicación elimina la credencial local y dirige al usuario al inicio de sesión. |
| **validaciones** | 1. El correo y la contraseña son obligatorios. 2. El correo debe eliminar espacios exteriores, tener un formato válido y normalizarse para su comparación. 3. La contraseña no debe recortarse ni normalizarse y debe verificarse contra el hash seguro almacenado. 4. Las credenciales deben validarse en el servidor y los errores no deben revelar si el correo pertenece a una cuenta registrada. 5. La sesión debe ser privada, segura, tener expiración y no incluirse en la URL. 6. El usuario solo puede consultar proyectos a los que pertenece e invitaciones dirigidas a su cuenta. 7. Cerrar sesión debe invalidar la credencial tanto en el servidor como en la aplicación. |
| **Mensaje de Sistema** | 1. Inicio exitoso: “Sesión iniciada correctamente”. 2. Datos incompletos o correo inválido: “Ingresa un correo electrónico válido y tu contraseña”. 3. Credenciales incorrectas: “El correo o la contraseña no son correctos”. 4. Error de comunicación o del servidor: “No fue posible iniciar sesión. Inténtalo nuevamente”. 5. Cierre exitoso: “Sesión cerrada correctamente”. |
| **Salida de Sistema** | 1. Sesión segura asociada con el usuario. 2. Identidad e información básica del usuario disponibles en la aplicación. 3. Proyectos e invitaciones accesibles para el usuario identificados. 4. Usuario ubicado en el área autenticada o, si cerró sesión, en la pantalla de acceso. |
