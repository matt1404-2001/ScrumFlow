| **CU-01** | **Registrar Sprint Review** |
| **Fecha de creación** | 06/10/2026 |
| **Versión** | 1 |
| **Autor** | Equipo |
| **Actores** | **Miembro del proyecto:** registra asistentes, resultados y retroalimentación. **Administrador del proyecto:** confirma la finalización de la Review. **Stakeholder:** participa externamente; sus datos y comentarios son registrados por un miembro. **Sistema:** obtiene el incremento y conserva el registro de la Review. |
| **Requisitos previos** | 1. El usuario debe haber iniciado sesión y ser miembro del proyecto. 2. El Sprint debe encontrarse En cierre y su tablero debe estar bloqueado. 3. La Sprint Review no debe haberse completado. 4. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Inspeccionar el resultado del Sprint y el cumplimiento del Sprint Goal. 2. Presentar los elementos que forman el incremento. 3. Registrar asistentes, resultados y retroalimentación. 4. Adaptar el Product Backlog según lo aprendido. 5. Habilitar la Sprint Retrospective. |
| **Descripción** | Este caso de uso permite registrar la Sprint Review de un Sprint En cierre. El sistema presenta el Sprint Goal, los elementos terminados que forman el incremento y el trabajo incompleto. Los miembros registran asistentes, resultados, retroalimentación y decisiones. La información obtenida puede utilizarse para crear o actualizar elementos del Product Backlog. Al completar la Review, se habilita la Retrospectiva, pero el Sprint todavía no se considera finalizado. |
| **Entradas** | **Proporcionadas por el usuario:** asistentes, stakeholders externos, resultados, retroalimentación, decisiones, conclusión y cambios requeridos en el Product Backlog.  **Internas del sistema:** Sprint Goal, Product Goal, elementos terminados, confirmaciones de la Definition of Done, elementos incompletos y estado de la Review.  **Disparador:** el caso comienza cuando un miembro accede al paso “Sprint Review” desde la pantalla de cierre del Sprint. |
| **Secuencia normal** | 1. El miembro accede al cierre del Sprint y selecciona “Sprint Review”. 2. El sistema comprueba que el Sprint esté En cierre y que la Review permanezca pendiente. 3. El sistema muestra el Sprint Goal, el incremento y los elementos incompletos. 4. El miembro registra los asistentes y stakeholders participantes. 5. El equipo registra los resultados, la retroalimentación y las decisiones obtenidas. 6. Cuando corresponde, el miembro crea o actualiza elementos del Product Backlog a partir de la retroalimentación. 7. El miembro registra una conclusión y guarda la Review. 8. Un administrador selecciona “Completar Review”. 9. El sistema valida la información y registra quién completó la Review y cuándo. 10. La Review queda en modo de solo lectura y el sistema habilita la Sprint Retrospective. 11. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | **A1. Guardar Review incompleta:** el usuario guarda la información como Borrador y puede continuarla después, sin habilitar todavía la Retrospectiva.  **A2. No existe incremento:** si ningún elemento cumple la Definition of Done, el sistema muestra que el incremento está vacío, pero permite registrar los resultados y completar la Review.  **A3. Adaptar el Product Backlog:** el miembro crea o actualiza elementos siguiendo las reglas de gestión y refinamiento del backlog; el trabajo incompleto no se mueve automáticamente al siguiente Sprint.  **A4. Información insuficiente:** si faltan asistentes, resultados o conclusión, el sistema conserva el Borrador e indica qué debe completarse.  **A5. Estado no permitido:** si el Sprint no está En cierre o la Review ya fue completada, el sistema impide modificarla y muestra la información disponible para consulta.  **A6. Finalización no autorizada o error del sistema:** el sistema no completa la Review, conserva la información guardada y muestra el error correspondiente. |
| **validaciones** | 1. La Review solo puede registrarse para un Sprint En cierre y debe completarse antes de la Retrospectiva. 2. El incremento incluye únicamente elementos Terminados con la Definition of Done confirmada; el trabajo incompleto se muestra por separado. 3. Los asistentes pueden ser integrantes registrados o stakeholders externos identificados por nombre, sin crearles una cuenta. 4. Para completar la Review deben existir al menos un asistente, resultados y una conclusión. 5. Los cambios al Product Backlog deben cumplir las reglas de gestión y refinamiento correspondientes. 6. Solo un administrador puede completar la Review; una vez completada queda en modo de solo lectura. 7. Completar la Review habilita la Retrospectiva, pero no finaliza el Sprint. |
| **Mensaje de Sistema** | 1. Borrador guardado: “Sprint Review guardada”. 2. Review completada: “Sprint Review completada. Ya puedes realizar la Retrospectiva”. 3. Incremento vacío: “Ningún elemento cumplió la Definition of Done durante este Sprint”. 4. Información incompleta: “Registra los asistentes, resultados y conclusión de la Review”. 5. Estado no permitido: “La Sprint Review no puede modificarse en el estado actual”. 6. Error general: “No fue posible guardar o completar la Sprint Review”. |
| **Salida de Sistema** | 1. Sprint Review guardada o completada. 2. Asistentes, resultados, retroalimentación, decisiones y conclusión registrados. 3. Incremento y trabajo incompleto conservados como parte del cierre. 4. Product Backlog actualizado cuando corresponda. 5. Sprint Retrospective habilitada después de completar la Review. |
