| **CU-01** | **Registrar Daily Scrum** |
| **Fecha de creación** | 06/10/2026 |
| **Versión** | 1 |
| **Autor** | Equipo |
| **Actores** | **Miembro del proyecto:** puede iniciar la Daily, unirse y publicar mensajes. **Miembro autorizado:** usuario que inició la Daily o administrador del proyecto; puede finalizarla. **Sistema:** administra el estado, la asistencia, los mensajes y los impedimentos. |
| **Requisitos previos** | 1. El usuario debe haber iniciado sesión y ser miembro del proyecto. 2. Debe existir un Sprint Activo. 3. Debe existir una Daily Programada para la fecha y el Sprint actuales. 4. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Iniciar y finalizar explícitamente la Daily Scrum. 2. Registrar participantes, horas de ingreso y ausentes. 3. Proporcionar un espacio para mensajes, avances e impedimentos. 4. Conservar la sesión como parte del historial del Sprint. |
| **Descripción** | Este caso de uso permite administrar una Daily Scrum desde que está Programada hasta su finalización. Un miembro inicia explícitamente la reunión y el sistema registra la fecha, hora de inicio, usuario iniciador e integrantes esperados. Durante la sesión, los demás miembros pueden unirse y participar mediante mensajes, avances o impedimentos. Al finalizar, el sistema registra la hora de cierre, determina los ausentes y deja la Daily disponible únicamente para consulta. No se requiere videollamada ni comunicación en tiempo real. |
| **Entradas** | **Proporcionadas por los miembros:** acciones “Iniciar Daily”, “Unirse” y “Finalizar Daily”; mensajes, avances, impedimentos y elemento relacionado opcional.  **Internas del sistema:** Sprint Activo, fecha actual, estado de la Daily, integrantes del proyecto, asistencias, mensajes y elementos del Sprint.  **Disparador:** el caso comienza cuando un miembro selecciona “Iniciar Daily” si la sesión está Programada, o selecciona “Unirse” si ya está En curso. |
| **Secuencia normal** | 1. Un miembro accede al área de la Daily Scrum. 2. El sistema comprueba que exista un Sprint Activo y muestra la Daily del día en estado Programada. 3. El miembro selecciona “Iniciar Daily”. 4. El sistema valida que no exista otra Daily iniciada para la misma fecha y Sprint. 5. El sistema cambia la Daily a En curso y registra la fecha, hora de inicio, usuario iniciador y lista de integrantes esperados. 6. El usuario iniciador queda registrado como primer participante con su hora de ingreso. 7. Los demás integrantes acceden a la sesión y seleccionan “Unirse”. 8. El sistema registra una asistencia y hora de ingreso para cada participante. 9. Los participantes publican mensajes, avances o impedimentos y pueden relacionarlos con un elemento del Sprint. 10. El sistema conserva cada publicación con su autor y hora. 11. El miembro autorizado selecciona “Finalizar Daily”. 12. El sistema registra la hora de cierre, determina los ausentes y cambia la Daily a Finalizada. 13. La sesión queda disponible como historial de solo lectura y la guía del proyecto se actualiza. 14. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | **A1. Otro miembro inició la Daily primero:** si la sesión ya está En curso, el sistema no vuelve a iniciarla y muestra la opción “Unirse”.  **A2. El usuario ya se había unido:** el sistema abre la sesión sin duplicar su asistencia y le permite continuar participando.  **A3. La Daily ya está Finalizada:** el sistema permite consultar participantes, ausentes y mensajes, pero no admite nuevas participaciones o publicaciones.  **A4. No existe Sprint Activo o Daily Programada:** el sistema impide iniciar o unirse a la sesión e informa que no hay una Daily disponible.  **A5. Mensaje o relación inválida:** si la publicación está vacía o el elemento relacionado no pertenece al Sprint, el sistema no la guarda y solicita corregirla.  **A6. Finalización no autorizada:** si el usuario no inició la Daily ni es administrador, el sistema rechaza la acción y mantiene la sesión En curso.  **A7. Error de comunicación o almacenamiento:** el sistema conserva el estado anterior y no registra asistencias, publicaciones o cierres incompletos. |
| **validaciones** | 1. Los estados permitidos son Programada, En curso y Finalizada, siguiendo ese orden sin retrocesos. 2. Solo puede existir una Daily por fecha y Sprint, y únicamente puede iniciarse cuando el Sprint está Activo. 3. Al iniciar deben registrarse fecha, hora, usuario iniciador e integrantes esperados; el iniciador cuenta como primer participante. 4. Un usuario solo puede registrar una asistencia y únicamente puede unirse mientras la Daily esté En curso. 5. Solo los participantes pueden publicar mensajes; el contenido debe ser válido y cualquier elemento relacionado debe pertenecer al Sprint actual. 6. Los impedimentos quedan abiertos hasta que un miembro los marque como resueltos. 7. Solo el usuario iniciador o un administrador puede finalizar la Daily. 8. Al finalizar deben registrarse la hora de cierre y los ausentes; posteriormente la sesión queda en modo de solo lectura. |
| **Mensaje de Sistema** | 1. Inicio exitoso: “Daily Scrum iniciada”. 2. Ingreso exitoso: “Te uniste a la Daily Scrum”. 3. Publicación registrada: “Actualización publicada correctamente”. 4. Impedimento registrado: “Impedimento agregado al seguimiento del proyecto”. 5. Sesión no disponible: “No existe una Daily disponible para este momento”. 6. Finalización no autorizada: “No tienes permiso para finalizar esta Daily”. 7. Cierre exitoso: “Daily Scrum finalizada”. 8. Error general: “No fue posible completar la operación. Inténtalo nuevamente”. |
| **Salida de Sistema** | 1. Daily registrada con estado, fecha, horas de inicio y cierre y usuario iniciador. 2. Lista de integrantes esperados, participantes, horas de ingreso y ausentes. 3. Mensajes, avances e impedimentos conservados con autor y hora. 4. Daily Finalizada disponible como historial de solo lectura. 5. Guía del proyecto actualizada con el estado de la Daily y los impedimentos abiertos. |
