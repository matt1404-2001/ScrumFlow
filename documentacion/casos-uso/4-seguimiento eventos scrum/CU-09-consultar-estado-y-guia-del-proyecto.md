| **CU-01** | **Consultar estado y guía del proyecto** |
| **Fecha de creación** | 06/10/2026 |
| **Versión** | 1 |
| **Autor** | Equipo |
| **Actores** | **Miembro del proyecto:** consulta el estado y selecciona acciones recomendadas. **Sistema:** obtiene la información del proyecto y genera recomendaciones mediante reglas. |
| **Requisitos previos** | 1. El usuario debe haber iniciado sesión. 2. Para consultar un proyecto, el usuario debe ser miembro. 3. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Presentar el estado actual del proyecto y del Sprint. 2. Indicar la siguiente actividad recomendada. 3. Mostrar configuraciones pendientes, impedimentos y eventos próximos. 4. Facilitar el acceso a la función correspondiente. |
| **Descripción** | Este caso de uso permite consultar un resumen operativo del proyecto. El sistema analiza su configuración, Product Backlog, Sprint, Dailies, impedimentos y eventos de cierre para indicar qué actividad corresponde realizar. Las recomendaciones se generan mediante reglas simples, sin inteligencia artificial, y no modifican automáticamente la información del proyecto. |
| **Entradas** | **Proporcionadas por el usuario:** proyecto seleccionado y selección opcional de una recomendación.  **Internas del sistema:** invitaciones, equipo, responsabilidades, Product Goal, Definition of Done, Product Backlog, Sprint vigente, avance, fechas, Dailies, impedimentos, Review y Retrospectiva.  **Disparador:** el caso comienza cuando el usuario accede al área “Resumen”. |
| **Secuencia normal** | 1. El miembro accede al Resumen del proyecto. 2. El sistema comprueba su sesión y membresía. 3. El sistema obtiene la configuración y el estado actual del proyecto. 4. El sistema determina la etapa del ciclo Scrum y calcula la recomendación principal. 5. El sistema calcula el avance del Sprint y localiza impedimentos o actividades pendientes. 6. La aplicación muestra el Product Goal, Sprint Goal, estado del Sprint, avance, recomendación principal y alertas secundarias. 7. El miembro consulta la información y puede seleccionar una recomendación. 8. La aplicación dirige al usuario al área correspondiente sin modificar datos automáticamente. 9. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | **A1. Invitación pendiente o ausencia de proyectos:** el sistema recomienda revisar la invitación o crear un proyecto.  **A2. Configuración incompleta:** si faltan integrantes, responsabilidades Scrum o Definition of Done, el sistema recomienda completar la configuración del equipo.  **A3. Product Backlog o planificación pendiente:** si falta el Product Goal, no existen elementos o no hay Sprint actual, el sistema recomienda gestionar el backlog o planificar un Sprint. Si existe un Borrador, indica qué falta para activarlo.  **A4. Sprint Activo:** el sistema muestra el avance, la Daily pendiente del día laboral, los impedimentos abiertos y una advertencia cuando faltan dos días o menos para finalizar.  **A5. Sprint En cierre:** el sistema recomienda realizar la Sprint Review o la Sprint Retrospective según el evento pendiente.  **A6. Sprint Finalizado:** el sistema recomienda refinar el Product Backlog y planificar el siguiente Sprint.  **A7. Acceso no autorizado o error del sistema:** la aplicación no muestra información del proyecto e informa el problema. |
| **validaciones** | 1. El usuario debe mantener una sesión válida y solo puede consultar proyectos en los que sea miembro. 2. Las recomendaciones deben calcularse con la información actual, sin almacenar estados duplicados ni utilizar inteligencia artificial. 3. El avance debe obtenerse de los elementos Pendientes, En progreso y Terminados del Sprint vigente. 4. La Daily solo debe mostrarse como pendiente durante un día laboral de un Sprint Activo cuando todavía no exista un registro para ese día. 5. Solo deben mostrarse como pendientes los impedimentos que no hayan sido resueltos. 6. La advertencia de cierre debe aparecer cuando falten dos días o menos o cuando la fecha final haya llegado. 7. Las recomendaciones únicamente orientan o dirigen al usuario; no deben crear, modificar ni finalizar información automáticamente. |
| **Mensaje de Sistema** | 1. Configuración pendiente: “Completa el equipo y los acuerdos del proyecto”. 2. Backlog pendiente: “Define el Product Goal y prepara el Product Backlog”. 3. Planificación pendiente: “No existe un Sprint actual. Planifica el siguiente Sprint”. 4. Daily pendiente: “La Daily Scrum de hoy está pendiente”. 5. Impedimentos abiertos: “El equipo tiene impedimentos pendientes de resolver”. 6. Cierre próximo: “El Sprint está próximo a finalizar. Prepara su cierre”. 7. Evento pendiente: “Completa la Review y la Retrospectiva para finalizar el Sprint”. 8. Error general: “No fue posible obtener el estado del proyecto”. |
| **Salida de Sistema** | 1. Resumen actualizado del proyecto y del Sprint. 2. Recomendación principal calculada según la etapa actual. 3. Alertas de configuración, Daily, impedimentos o cierre mostradas cuando corresponda. 4. Acceso directo al área relacionada con la recomendación seleccionada. |
