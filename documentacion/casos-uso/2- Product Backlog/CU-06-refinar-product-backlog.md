| **CU-06** | **Refinar Product Backlog** |
| **Fecha de creación** | 05/10/2026 |
| **Versión** | 1 |
| **Autor** | Equipo |
| **Actores** | **Miembro del proyecto:** aclara, detalla o divide elementos. **Developers:** conservan la responsabilidad sobre la estimación. **Product Owner:** colabora en la comprensión y preparación de los elementos. **Sistema:** aplicación web, API y base de datos. |
| **Requisitos previos** | 1. El usuario debe haber iniciado sesión y ser miembro del proyecto. 2. El elemento debe existir y permanecer activo en el Product Backlog o en un Sprint en estado Borrador. 3. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Mejorar la claridad y preparación de los elementos. 2. Registrar estimaciones y criterios de aceptación. 3. Dividir elementos demasiado grandes en otros más pequeños. 4. Identificar qué elementos cuentan con información suficiente para considerarse durante la planificación. |
| **Descripción** | Este caso de uso permite refinar continuamente los elementos del Product Backlog desde su mismo panel de detalle. Los miembros pueden agregar aclaraciones y criterios de aceptación, mientras los Developers conservan la responsabilidad sobre la estimación. También pueden dividir un elemento grande en varios elementos independientes. El refinamiento no constituye una reunión formal ni administra fechas, responsables, estados o datos de ejecución del Sprint. |
| **Entradas** | **Proporcionadas por el usuario:** elemento seleccionado, aclaraciones, criterios de aceptación, estimación y datos para una posible división.  **Internas del sistema:** información actual del elemento, estado del Sprint relacionado, posición y prioridad dentro del backlog.  **Disparador:** el caso comienza cuando un miembro abre un elemento y selecciona la opción “Refinar”. |
| **Secuencia normal** | 1. El miembro abre un elemento del Product Backlog y selecciona “Refinar”. 2. El sistema muestra su descripción, aclaraciones, criterios de aceptación y estimación actuales. 3. El miembro completa o actualiza la información necesaria. 4. La aplicación valida los textos y la estimación. 5. El miembro selecciona “Guardar refinamiento”. 6. El servidor comprueba la membresía y que el elemento pueda modificarse. 7. El sistema guarda los cambios y actualiza el indicador de preparación del elemento. 8. La aplicación muestra el detalle actualizado y confirma la operación. 9. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | **A1. Dividir un elemento:** el miembro proporciona al menos dos títulos; el sistema crea nuevos elementos independientes en la posición del original, conserva su prioridad y retira el elemento dividido. Si el original posee historial, permanece conservado como retirado.  **A2. Información insuficiente o estimación inválida:** si una aclaración o criterio está vacío, o la estimación no es un número entero positivo, el sistema señala los datos que deben corregirse.  **A3. Elemento en ejecución o cierre:** si pertenece a un Sprint Activo o En cierre, el sistema impide refinarlo desde el Product Backlog. Sus cambios operativos deben gestionarse desde el Sprint.  **A4. Acceso no autorizado o error del sistema:** el servidor rechaza la operación, conserva la información anterior e informa el problema. |
| **validaciones** | 1. El usuario debe mantener una sesión válida, ser miembro del proyecto y seleccionar un elemento activo. 2. Las aclaraciones y los criterios deben contener texto válido y mostrarse sin ejecutar HTML o scripts. 3. La estimación es opcional durante el refinamiento, pero cuando se registre debe ser un número entero positivo y será necesaria antes de activar un Sprint que incluya el elemento. 4. Un elemento se considera preparado cuando posee título, descripción y estimación; los criterios de aceptación proporcionan detalle adicional. 5. La división requiere al menos dos nuevos elementos y debe completarse totalmente o cancelarse totalmente. 6. Dividir no debe crear una jerarquía de épicas, historias o subtareas; los resultados son elementos independientes. 7. Un elemento asociado con un Sprint Activo o En cierre no puede refinarse desde esta función. |
| **Mensaje de Sistema** | 1. Actualización exitosa: “Elemento refinado correctamente”. 2. División exitosa: “Elemento dividido correctamente”. 3. Estimación inválida: “Ingresa una estimación válida”. 4. División incompleta: “Agrega al menos dos elementos para realizar la división”. 5. Operación no permitida: “El elemento no puede refinarse mientras el Sprint está en ejecución o cierre”. 6. Error general: “No fue posible guardar el refinamiento. Inténtalo nuevamente”. |
| **Salida de Sistema** | 1. Elemento actualizado con aclaraciones, criterios de aceptación y estimación. 2. Indicador de preparación actualizado. 3. Nuevos elementos independientes creados cuando se realiza una división. 4. Product Backlog conservado con el orden y la prioridad correspondientes. |
