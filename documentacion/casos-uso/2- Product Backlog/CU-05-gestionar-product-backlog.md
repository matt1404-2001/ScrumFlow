| **CU-05** | **Gestionar Product Backlog** |
| **Fecha de creación** | 05/10/2026 |
| **Versión** | 1 |
| **Autor** | Equipo |
| **Actores** | **Miembro del proyecto:** consulta, crea, edita y ordena elementos. **Product Owner:** conserva la responsabilidad sobre el Product Goal y el orden final del backlog. **Administrador del proyecto:** puede retirar o eliminar elementos. **Sistema:** aplicación web, API y base de datos. |
| **Requisitos previos** | 1. El usuario debe haber iniciado sesión. 2. El proyecto debe existir, estar seleccionado y contener al usuario como miembro. 3. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Mantener el Product Goal del proyecto. 2. Crear, consultar, editar y ordenar elementos del Product Backlog. 3. Registrar prioridades y fechas de planificación. 4. Retirar elementos sin perder información histórica. |
| **Descripción** | Este caso de uso permite a los miembros administrar el Product Backlog del proyecto. Desde una misma área pueden mantener el Product Goal y crear, consultar, editar, priorizar u ordenar elementos de trabajo. Cada elemento contiene inicialmente título, descripción, prioridad y posición. La estimación, los criterios de aceptación, las aclaraciones y la división se atienden durante el refinamiento. Las fechas, responsables, estados, checklist, comentarios e impedimentos se administran únicamente cuando el elemento forma parte de un Sprint. |
| **Entradas** | **Proporcionadas por el usuario:** Product Goal, título, descripción, prioridad, nueva posición y acción solicitada.  **Internas del sistema:** identidad del usuario, membresía, elementos existentes, orden actual, asociación con Sprints e historial.  **Disparador:** el caso comienza cuando un miembro accede al área “Product Backlog”. |
| **Secuencia normal** | 1. El miembro accede al Product Backlog del proyecto. 2. El sistema comprueba su membresía y muestra el Product Goal y la lista ordenada de elementos. 3. El miembro selecciona “Crear elemento”. 4. El sistema muestra el formulario con título, descripción y prioridad. 5. El miembro completa la información y selecciona “Guardar”. 6. La aplicación normaliza y valida los datos. 7. El servidor vuelve a validar la información y crea el elemento. 8. El sistema lo ubica al final del Product Backlog y guarda su posición. 9. La aplicación muestra el backlog actualizado y confirma la creación. 10. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | **A1. Actualizar el Product Goal:** un miembro edita el objetivo y el sistema guarda el cambio, señalando que el Product Owner conserva la responsabilidad sobre su contenido.  **A2. Consultar o editar un elemento:** el miembro abre su detalle, modifica el título, descripción o prioridad y guarda los cambios.  **A3. Reordenar elementos:** el miembro cambia la posición de uno o varios elementos y el sistema guarda el nuevo orden; el Product Owner conserva la responsabilidad sobre el orden final.  **A4. Retirar o eliminar un elemento:** un administrador confirma la operación; si el elemento nunca participó en un Sprint se elimina, pero si posee historial se marca como retirado. Un elemento perteneciente a un Sprint activo no puede retirarse desde el Product Backlog.  **A5. Información inválida, acceso no autorizado o error del sistema:** el servidor rechaza la operación, no guarda cambios parciales e informa el problema correspondiente. |
| **validaciones** | 1. El usuario debe mantener una sesión válida y ser miembro del proyecto. 2. El Product Goal debe contener texto antes de activar un Sprint, aunque puede permanecer pendiente durante la configuración inicial. 3. Todo elemento requiere un título; la descripción es opcional y la prioridad debe ser Baja, Media o Alta. 4. Los textos deben almacenarse y mostrarse sin ejecutar HTML o scripts. 5. Los títulos no necesitan ser únicos, pero cada elemento debe tener un identificador y una posición dentro del backlog. 6. Un elemento no puede pertenecer simultáneamente a dos Sprints no finalizados. 7. Solo un administrador puede retirar o eliminar elementos; aquellos con historial deben conservarse como retirados y los asociados con un Sprint activo no pueden eliminarse desde esta función. |
| **Mensaje de Sistema** | 1. Creación exitosa: “Elemento creado correctamente”. 2. Actualización exitosa: “Product Backlog actualizado”. 3. Título faltante: “Ingresa un título para el elemento”. 4. Retiro exitoso: “Elemento retirado del Product Backlog”. 5. Operación no permitida: “El elemento no puede retirarse mientras pertenezca a un Sprint activo”. 6. Error general: “No fue posible actualizar el Product Backlog. Inténtalo nuevamente”. |
| **Salida de Sistema** | 1. Product Goal actualizado cuando corresponda. 2. Elemento creado, consultado, editado, ordenado, eliminado o retirado según la operación. 3. Product Backlog guardado con sus prioridades y orden actualizados. 4. Historial de participación del elemento conservado cuando corresponda. |
